# references/anti-patterns.md — 反模式红线 + 分层抽审 checklist

> 违反红线即不得宣告完成。SKILL.md「红线」节与此文件互相引用。

## 1. 反模式红线（12 条）

| # | 反模式 | 后果 | 强制做法 |
|:---|:---|:---|:---|
| 1 | 一次性批量生成全部文档 | 量大质低、无人 review、写完即烂 | 按层/按模块分批，每批人工确认后再继续 |
| 2 | AI 内容直接写正式文件 | 编造内容混入长期文档 | 一律先写 `*.draft`，`promote` 前人工 diff |
| 3 | docs 与代码分两次提交 | 文档 PR 永远悬挂 | 变更与产物同一次 git 提交 |
| 4 | 只记 what 不记 why | 半年后无人理解决策 | why 放人工区；机器区带 evidence |
| 5 | 契约写成源码翻译 | 失去调用者视角 | 按调用者视角：怎么调/返回什么/错了怎么看/示例 |
| 6 | 跳层（无架构直接写接口） | 契约堆砌无上下文 | 分层顺序硬约束：架构确认后再做模块/接口 |
| 7 | 用"像"代替真实抽取 | schema/签名与代码不一致 | 签名/路径/默认值全部来自 inventory 与源码 |
| 8 | 覆盖已有人工修改 | 修订丢失、信任崩塌 | AI-GEN marker 外内容重跑保留；人工区只增不自动改 |
| 9 | 用记忆代替扫描 | 路径/签名臆想 | 事实以 inventory/源码为准，起手先盘点 |
| 10 | 文档无来源/时间标注 | 不知何时与谁同步 | frontmatter 强制 source_commit/generated_at/hash |
| 11 | 抽取不确定 | 无法 CI 漂移检测 | inventory 两次跑 byte-identical（不写时间戳） |
| 12 | 重复造既有文档（双轨） | 两套文档互相漂移 | 项目已有 topic → 摘录+链接，不复制不覆盖 |

## 2. 分层抽审 checklist（每个确认点 / promote 前过一遍）

### 架构（ARCH-001）— 确认点①
- [ ] 一张图（ASCII/mermaid）：外部触发 → 核心组件 → 出口 完整
- [ ] 模块表覆盖全部顶层代码目录（模块/职责/入口/主要依赖）
- [ ] 至少 1 个端到端典型流程画完整
- [ ] 机器段与"人工补 why"分界清晰，免责句在

### 模块（modules/*）— 确认点②（每批）
- [ ] 四问齐全：做什么 / 为何存在 / 依赖什么 / 谁依赖它
- [ ] 对外依赖与 inventory deps 一致（python 自动；其他语言人工核对）
- [ ] 该模块符号登记锚点齐全（能过 check）

### 接口（api/*）— 确认点③（每批）
- [ ] 公开函数/端点条目齐全（对照 inventory）
- [ ] 每篇：用法 / 参数表 / 返回 / 错误 / 示例（示例来源标注）
- [ ] 抽样 ≥3 篇与源码核对：名字、默认值、必填可选、错误语义一致
- [ ] 示例取自测试，无编造调用

### 数据（data/*，可选）
- [ ] 字段全带含义；缺失显式 `unknown`
- [ ] 与真实模型/DDL 对照（不抄代码字符串当 schema）

### 全量收口
- [ ] `dev_docs.py check` ERROR=0（orphan/phantom/stale 全清或已 retired）
- [ ] index.md 覆盖率已更新；`report` 刷新过 baseline
- [ ] 所有 draft 已 promote（无残留 `.draft`）
- [ ] 与代码同一次提交

## 3. 使用时机

- extract 每层完成后、向用户发起确认前：过对应层 checklist。
- promote 前：至少抽 3 处 AI 填的语义对照源码。
- 宣告"文档完成"前：过「全量收口」清单。
- 低置信语言（lang-mapping 表）：任何人工抽审都必做。
