# references/evidence-protocol.md — 证据标注协议（防幻觉）

> 用途：dev-docs 产出是"从代码反建的长期文档"。为避免 AI 编造，每条非代码直抄的语义结论都必须给出证据等级。
> 原则：**机器能证明的交机器（inventory），AI 只能写它读了源码后能说清依据的话。**

## 1. 四级证据标签

| 标签 | 含义 | 何时用 | 示例 |
|:---|:---|:---|:---|
| **事实** | 直接可见于代码/配置文件/inventory | 签名、路径、路由、常量默认值、可见的调用 | `- 请求体：{username, password}（evidence: 事实，见 FastAPI 模型 AuthBody）` |
| **推断** | 从代码可推导，但需给依据 | 由调用关系/分支推断职责边界 | `- 此函数负责 token 刷新（evidence: 推断，调用链 refresh()→auth_middleware）` |
| **假设** | 代码无法证明，AI 猜的 | 无依据的意图、why | `- 推测支持多租户以隔离数据（evidence: 假设，需人工确认）` |
| **缺失** | 源码不足，无法确认 | 无测试、无类型、历史丢失 | `- 字段长度 unknown（evidence: 缺失，DDL 未入库）` |

## 2. 强制规则

1. 每个 `<fill>（evidence: …）`/语义句带且只带一个证据标签；机器行（签名/路径/ID）默认事实，可不重复标注。
2. **拿不准写 `unknown`，禁止省略或伪造**：字段长度/可空/索引、行为细节、外部依赖行为，凡代码没说清的一律 unknown。
3. `假设` 与 `推断` 在正式合入前默认要求人工确认点通过；`推断` 需在句内写明依据链（谁调用谁/哪个分支/哪个测试佐证）。
4. 免责句（architecture/module 文档开头一句即可）：
   > 本文档由 dev-docs 从代码反建，记录"代码里的实现事实"；设计意图（why）在「人工补充」区由维护者补写，未补前不代表历史决策。
5. 禁止为"显得完整"编造：不存在的参数、不存在的错误码、来源不明的调用方式，一律不写。

## 3. 常见误用对照

| ❌ 编造 | ✅ 正确 |
|:---|:---|
| `错误码 5002 表示余额不足`（源码无此码） | `错误处理：返回 4xx（evidence: 事实，见 raise HTTPException(400)）；具体码表 unknown` |
| `此接口幂等，可安全重试`（无依据） | `幂等性：未见去重键（evidence: 假设，需确认）` |
| 复制测试里不存在的调用当示例 | 示例必须来自 `tests/` 真实用例（见 api-doc-style） |
| 脑补字段 `status: enum(0,1,2)` | `status: unknown（evidence: 缺失，无枚举定义可查）` |

## 4. 人工区（why）与机器区（what）分界

- AI-GEN 区内写 **what/how**（接口长什么样、怎么调），带 evidence。
- 「人工补充」区写 **why**（为什么这么设计、取舍、历史），由维护者补；AI 可以**提议** why，但必须标假设并等待人工确认后才 promote。
- 抽查动作：合入前抽 ≥3 处 AI 填的语义句与源码对照（名字、默认值、错误处理、示例）。
